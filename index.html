ASP.NET Core MVC Basics

Understand routing, `Program.cs`, `IActionResult`, and how requests move from controller to view.

MVC Flow

Model
Data + validation rules
→
Controller
Handles requests
→
View
Renders HTML

A request hits a route, the controller runs logic, and the view returns HTML using model data.

Key Ideas

  • `{controller}/{action}/{id?}` is the standard route pattern.
  • `IActionResult` lets one action return a view, redirect, JSON, or `NotFound()`.
  • `AddControllersWithViews()` registers MVC services.
  • `MapControllerRoute()` wires the route table in `Program.cs`.

Real `Program.cs` Pattern From `TestDB`

using TestDB.Data;
using Microsoft.EntityFrameworkCore;

namespace TestDB
{
    public class Program
    {
        public static void Main(string[] args)
        {
            var builder = WebApplication.CreateBuilder(args);

            builder.Services.AddControllersWithViews();
            builder.Services.AddDbContext<StudentDBContext>(option =>
                option.UseSqlServer(builder.Configuration.GetConnectionString("SQLCON")));

            var app = builder.Build();

            app.UseHttpsRedirection();
            app.UseRouting();
            app.UseAuthorization();

            app.MapControllerRoute(
                name: "default",
                pattern: "{controller=Home}/{action=Index}/{id?}");

            app.Run();
        }
    }
}

`return View()`

Used when you want to render a Razor page and optionally pass model data into it.

`RedirectToAction()`

Used after POST actions like Create or Edit to prevent reposting the same form.

`NotFound()`

Used when an id does not match any existing item, like `Details(99)` on an empty list.

Models & Data Annotations

The `EmployeeDemo` model is the main validation example. Data annotations drive server validation and UI labels.

Real Employee Model Excerpt

public class Employee
{
    public int Id { get; set; }

    [Required(ErrorMessage = "First name is require.")]
    [StringLength(20, MinimumLength = 2, ErrorMessage ="Name between 2 and 20.")]
    [Display(Name = "First Name", Prompt ="e.g. Faris")]
    public string? FirstName { get; set; }

    [Required(ErrorMessage ="Email is require.")]
    [EmailAddress(ErrorMessage ="Invalid email formal.")]
    [Display(Name ="Email Address")]
    public string? Email { get; set; }

    [Required(ErrorMessage ="Salary is required.")]
    [Range(10000, 50000, ErrorMessage = "Salary between 10K and 50K.")]
    [DisplayFormat(DataFormatString = "{0:C}", ApplyFormatInEditMode = true)]
    public decimal Salary { get; set; }

    [DataType(DataType.Date)]
    public DateTime HireDate { get; set; }

    [DataType(DataType.Password)]
    public string? Password { get; set; }

    [Compare("Password", ErrorMessage ="Password and confired pass must be the same.")]
    public string? ConfirmPassword { get; set; }
}

`[Required]`

Rejects empty values for important fields like names, email, salary, and dates.

`[StringLength]`

Sets minimum and maximum character lengths. In the project, names must be 2 to 20 characters.

`[EmailAddress]`

Checks whether the submitted string looks like a valid email address.

`[Range]`

Restricts numeric values. The sample salary rule is between 10000 and 50000.

`[Display]`

Controls label text and prompt text shown in forms.

`[DataType]`

Hints to the UI how to render values, such as `Date` or `Password` fields.

`[Compare]`

Compares one property to another. Here it makes confirm password match password.

`[DisplayFormat]`

Controls output formatting, such as currency display for salary.

03

CRUD Operations

`EmployeesController` shows the full in-memory CRUD cycle: list, create, edit, details, and delete.

Controller Pattern

  • `Index()` returns the full list.
  • `Details(id)` finds one employee or returns `NotFound()`.
  • `Create()` GET shows the form.
  • `Create(Employee employee)` POST saves when `ModelState.IsValid` is true.
  • `Edit(id)` GET loads existing data.
  • `Edit(id, updatedEmployee)` POST updates each property.
  • `Delete(id)` GET shows a confirmation page.
  • `Delete(Employee employeeToDelete)` POST removes the item.

Why `ModelState.IsValid` Matters

Validation attributes run during model binding. If any rule fails, MVC keeps the invalid values, repopulates the form, and exposes error messages to the view. Only valid data should modify the list or database.

Real `EmployeesController` Excerpt

public IActionResult Create(Employee employee)
{
    if (ModelState.IsValid)
    {
        employee.Id = employees.Max(e => e.Id) + 1;
        employees.Add(employee);
        return RedirectToAction(nameof(Index));
    }
    return View(employee);
}

[HttpPost]
[ValidateAntiForgeryToken]
public IActionResult Edit(int id, Employee updatedEmployee)
{
    var existingEmployee = employees.FirstOrDefault(e => e.Id == id);
    if (existingEmployee == null)
    {
        return NotFound();
    }

    if (ModelState.IsValid)
    {
        existingEmployee.FirstName = updatedEmployee.FirstName;
        existingEmployee.LastName = updatedEmployee.LastName;
        existingEmployee.Email = updatedEmployee.Email;
        existingEmployee.Salary = updatedEmployee.Salary;
        existingEmployee.Mode = updatedEmployee.Mode;
        return RedirectToAction(nameof(Index));
    }
    return View(updatedEmployee);
}

Tag Helpers

Tag Helpers let normal HTML elements understand MVC concepts like routing, model binding, and validation.

Common Tag Helpers

  • `asp-for` binds an input or label to a model property.
  • `asp-action` builds a URL for a controller action.
  • `asp-controller` targets a different controller when needed.
  • `asp-route-id` passes route values like primary keys.
  • `asp-validation-for` prints field-level validation messages.
  • `asp-validation-summary` shows model-level errors.

`_ViewImports.cshtml`

@using EmployeeDemo
@using EmployeeDemo.Models
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers

Without `@addTagHelper`, `asp-for` and the other MVC helpers will not activate in Razor views.

Plain HTML

<label>First Name</label>
<input name="FirstName" />
<span class="text-danger"></span>

Razor With Tag Helpers

<label asp-for="FirstName"></label>
<input asp-for="FirstName" class="form-control" />
<span asp-validation-for="FirstName" class="text-danger"></span>

Razor Views

Razor combines HTML with C# syntax so a controller can pass model data into a dynamic page.

Real `StudentsController` Pattern

private static List<Student> students = new List<Student>
{
    new Student{Id=1, Name="Faris", Program="SWE", Email="f@asu.edu.jo", EnrollmentDate=DateTime.Now },
    new Student{Id=2, Name="Ahmad", Program="CS", Email="a@asu.edu.jo", EnrollmentDate=DateTime.Now },
    new Student{Id=3, Name="Sami", Program="Cyber", Email="f@asu.edu.jo", EnrollmentDate=DateTime.Now },
};

public IActionResult Index()
{
    return View(students);
}

Real Razor List View

@model IEnumerable<StudentsManagement.Models.Student>

<tbody>
    @foreach (var element in Model)
    {
        <tr>
            <td>@element.Id</td>
            <td>@element.Name</td>
            <td>@element.Email</td>
            <td>@element.Program</td>
        </tr>
    }
</tbody>

`@model`

Declares the type the view expects, such as `IEnumerable<Student>`.

`@Model`

Gives access to the strongly typed object passed from the controller.

`@foreach`

Loops over items from the model to render rows or cards.

`@if`

Shows conditional UI, such as a warning when a list is empty.

`@{ }`

Embeds a block of C# statements inside a Razor view.

`ViewData["Title"]`

Sets shared values consumed by the layout page.

`_Layout.cshtml`

Defines the shared shell: header, footer, and `RenderBody()` area.

`@section Scripts`

Lets a view inject page-specific scripts into the layout.

`TestDB` shows how to move from a static list to a real SQL Server-backed application.

`DbContext` and `DbSet`

{
    public StudentDBContext(DbContextOptions<StudentDBContext> options) : base(options)

Model Used By EF Core

public class Student
{

    public string? StudentName { get; set; }
    public string? Program { get; set; }
}

Migration Output

migrationBuilder.CreateTable(
    name: "students",
    columns: table => new
    {
        StudentId = table.Column<int>(type: "int", nullable: false)
            .Annotation("SqlServer:Identity", "1, 1"),
        StudentName = table.Column<string>(type: "nvarchar(max)", nullable: true),
        Program = table.Column<string>(type: "nvarchar(max)", nullable: true)
    },
    constraints: table =>
    {
        table.PrimaryKey("PK_students", x => x.StudentId);
    });

`Add-Migration m1`

Generates a migration class based on model changes.

`Update-Database`

Applies pending migrations to SQL Server.

Connection String

`UseSqlServer(builder.Configuration.GetConnectionString("SQLCON"))` reads the connection from configuration.

07

Relationships

The `Company` project demonstrates a one-to-many relationship: one department can have many employees.

Real `Department` Model

public class Department
{
    [Key]
    public int DeptId { get; set; }
    public string? DeptName { get; set; }
    public IEnumerable<Employee>? employees { get; set; }
}

Real `Employee` Model

public class Employee
{
    [Key]
    public int EmpId { get; set; }
    public string? EmpName { get; set; }
    public int DeptId { get; set; }
    public Department? Department { get; set; }
}

How EF Understands This

  • `DeptId` acts as the foreign key by naming convention.
  • `Department` is the reference navigation property.
  • `IEnumerable<Employee>` is the collection navigation property.
  • `[Key]` marks the primary key field explicitly.

Eager Loading

var departments = context.Departments
    .Include(d => d.employees)
    .ToList();

`Include()` loads related records in the same query instead of deferring them.

08

In-Memory vs Database

Your projects show both approaches, which makes them useful for comparing early learning setups against production-style persistence.

In-Memory List

  • Fastest way to learn MVC actions and views.
  • No database setup required.
  • Data resets whenever the app restarts.
  • Good for demos, labs, and early CRUD practice.

EF Core + SQL Server

  • Data persists between runs.
  • Supports relationships, migrations, and querying.
  • Needs configuration, connection strings, and schema management.
  • Closer to real production projects.
